# 可复现的读取性能测量

使用标准库脚本，不需要安装压测工具。仅发送 GET，不写链、不改服务配置。
先建立演示数据，再从实际使用的入口执行：

```powershell
python -X utf8 -B scripts/benchmark.py --url 'http://localhost:8080/api/public/trace?batchNo=DEMO-showcase01-SALE'
```

默认 1 次预热、20 次请求、并发 1。输出成功数、分类失败数、成功请求 P50/P95/P99、
总耗时和成功请求每秒数；HTTP 200 携带业务错误码也算失败。任何测量请求失败时退出码为 1。
分位数使用 nearest-rank，只统计成功响应；全失败时分位数为 null。

登录接口获得令牌后，可在当前进程环境设置 `BENCHMARK_TOKEN` 测试机构列表：

```powershell
$env:BENCHMARK_TOKEN = Read-Host '当前账户 JWT' -MaskInput
python -X utf8 -B scripts/benchmark.py --url 'http://localhost:8080/api/products?page=1&size=20' --requests 20
```

请勿把令牌放到 URL 或提交到结果文件。脚本将结果写到标准输出，是否保存由执行者决定。
修改并发使用 `--concurrency`；公开查询默认每 IP 每分钟 30 次，下载也共享 public 配额。
预热和其他浏览器请求都计入限流，看到 429 就如实记录，不能关闭限流后隐去测试条件。

## 必须一同记录的条件

| 项目 | 记录内容 |
|---|---|
| 软件版本 | Git SHA、FISCO/WeBASE/MySQL/MinIO 版本 |
| 环境 | CPU、内存、节点数量、群组、同机还是跨主机、是否经过 nginx |
| 数据 | 产品总数、单产品记录数、文件大小 |
| 查询 | 普通分页 / 关键词筛选 / 公开批次查询 |
| 缓存 | 首次未预热（`--warmup 0`）与预热后分开，说明是否刚启动服务 |
| 负载 | 请求数、并发、超时、成功与错误数、是否限流 |

单次冷查询只是样本，20 次请求也不能支撑稳定 P99 的结论。统计规模、冷暖缓存与限流
策略应按实际实验目标设计；不能将读取每秒数写成区块链 TPS，写链还包含签名、共识和回执等待。
当前组合筛选仍遍历读缓存，需特别比较数据量增长时的冷启动延迟。

## 当前证据

本轮仅验证了脚本的错误分类、分位数计算和参数行为，没有执行真实链性能测量，
因此不提供虚构的吞吐量或延迟数字。正式测量结果应随上述环境条件和原始 JSON 一起归档。
